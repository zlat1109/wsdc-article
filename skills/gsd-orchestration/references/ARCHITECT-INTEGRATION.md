# Architectural Integration Guide (agent-architect)

This guide explains how GSD integrates with agent-architect for professional architectural design of ANY complex phase.

---

## 🎯 Overview

GSD offers **agent-architect** for EVERY `gsd discuss [N]` command.

**When**: Every phase discussion (user chooses whether to accept)
**What**: Runs agent-architect's 5-phase professional architectural interview
**Result**: Architecture saved to `ARCHITECTURE.md`, used in planning

**Works for ANY complex system**: API design, data pipelines, AI agents, microservices, frontends, CLIs, etc.

---

## 🔍 How Integration Works

### Automatic Offer (Every Phase)

During `gsd discuss [N]`, GSD **always** offers agent-architect:

```bash
/gsd discuss 2

GSD: "For this phase, I can run a professional architectural interview
     using agent-architect. This covers:

     - Strategy & pattern selection (ReAct / Planner / Combined)
     - Team definition with dual templates (Identity + Task Dispatch)
     - Tool architecture (built-in, custom MCP, external MCP, RAG)
     - Output destination (local files, Notion, Slack, API endpoints via MCP)
     - Orchestration pattern with optional guiding Skill
     - Interaction mode (one-shot / conversational / plan-first)
     - Production readiness (guardrails, security, tool confirmation UI)
     - SDK configuration (tool permissions, setting_sources, prompts-as-md)

     Works for ANY complex system — not just AI agents.

     What would you like to do?"

Options:
[1] Run agent-architect interview (Recommended - ensures thorough planning)
[2] Continue with standard GSD discuss
```

**User controls**: Choose [1] for thorough architectural design, or [2] for lighter discussion.

### Why Use agent-architect?

agent-architect provides a structured 5-phase design process:

1. **Phase 1: Strategy** - Problem definition, pattern selection (ReAct/Planner/etc.)
2. **Phase 2: Team/Tools** - Components/agents/modules definition, tooling selection
3. **Phase 3: Orchestration** - Architecture pattern (Single/Pipeline/Orchestrator/Parallel)
4. **Phase 4: Production** - Guardrails, security, monitoring, metrics
5. **Phase 5: Approval** - Review and approve before implementation

**Even for non-AI projects**, this ensures:
- Proper architectural decisions upfront
- Security and production readiness
- Tool/library selection with reasoning
- Implementation strategy approval

### Standard GSD Phase (without architect)


### With agent-architect (Recommended for complex phases)

```
/gsd discuss N
├─ Detect AI keywords
├─ Ask: "Run agent-architect?"
│
├─ If YES:
│   ├─ Launch agent-architect
│   ├─ Phase 1: Pattern (ReAct/Planner/Combined)
│   ├─ Phase 2: Agents & Tools
│   ├─ Phase 3: Orchestration
│   ├─ Phase 4: Guardrails & Production
│   ├─ Phase 5: Approval
│   └─ Save → ARCHITECTURE.md
│
├─ Continue standard discuss
└─ Create CONTEXT.md (decisions)

/gsd plan N
├─ Load: ARCHITECTURE.md + CONTEXT.md
├─ Break architecture into atomic tasks
├─ Reference architecture decisions in plans
└─ Create PLAN-X.md files

/gsd execute N
├─ Task 1: Implement agents (fresh context)
├─ Task 2: Implement tools (fresh context)
```

## Agent Team

### Agent 1: Triage Agent

**Identity (system_prompt):**
- **Role**: Customer request classifier
- **Goal**: Categorize support requests into priorities
- **Backstory**: Expert at understanding customer intent

**Task Dispatch Template:**
- **Process**: 1) Read request, 2) Classify intent, 3) Assign priority
- **Input Format**: Raw customer message text
- **Guidelines**: Respond within 1 turn, never guess — ask for clarification
- **Output Format**: JSON `{ "category": str, "priority": 1-5, "reasoning": str }`

**Tools**:
- Built-in: Read, WebSearch
- Custom: `classify_intent` (MCP tool)

**Prompt File**: `prompts/triage_agent.md`

### Agent 2: Knowledge Base Agent

**Identity (system_prompt):**
- **Role**: Information retrieval specialist
- **Goal**: Find relevant answers from knowledge base
- **Backstory**: Expert at navigating documentation

**Task Dispatch Template:**
- **Process**: 1) Search KB with query, 2) Rank results, 3) Compose answer
- **Input Format**: Category + customer question
- **Guidelines**: Always cite sources using [KB-#] notation
- **Output Format**: Answer text with citations + confidence score

**Tools**:
- RAG: ChromaDB vector search over support docs
- Custom: `search_kb`, `get_article`

**Prompt File**: `prompts/kb_agent.md`

## 🔄 Context Loading Rules

### During `gsd discuss N` (AI-detected)

**Load**:
- PROJECT.md (full)
- ROADMAP.md (phase N only)
- STATE.md (decisions)

**After agent-architect**:
- ARCHITECTURE.md created
- CONTEXT.md created (with reference to ARCHITECTURE.md)

### During `gsd plan N` (AI phase)

**Load**:
- PROJECT.md (tech stack section)
- ROADMAP.md (phase N only)
- **ARCHITECTURE.md** ← Architecture decisions
- CONTEXT.md ← Discussion decisions
- Previous SUMMARY.md (if exists)

**Use ARCHITECTURE.md for**:
- Agent definitions (identity + task dispatch templates) → Task 1: Implement agents + prompts
- Tool specifications (built-in + custom MCP + output destination) → Task 2: Implement tools + MCP
- Orchestration logic + guiding skill + interaction mode → Task 3: Orchestration + loop

### During `gsd execute N` (per task)

**Fresh context per task**:

**Task 1: Implement agents + prompts**
- PROJECT.md (tech stack only)
- PLAN-1.md
- ARCHITECTURE.md (agent definitions section)
- Create prompt files as `prompts/*.md`

**Task 2: Implement tools + MCP**
- PROJECT.md (tech stack only)
- PLAN-2.md
- ARCHITECTURE.md (tools + output destination sections)

**Task 3: Orchestration + skill + loop**
- PROJECT.md (tech stack only)
- PLAN-3.md
- ARCHITECTURE.md (orchestration + interaction mode sections)
- agents/ and tools/ code (for integration)

**Critical**: Context cleared between tasks!

```markdown
Before standard discussion, check if phase involves AI agents:

1. **Scan phase description** for keywords:
   - "AI agent", "agent system", "autonomous", "orchestrator", "subagent"

   ```

   [1] Run agent-architect interview (recommended)
       → 5-phase architectural design
       → Outputs ARCHITECTURE.md

   [2] Continue with standard GSD discuss

   ```
3. **If user chooses [1]**:
   - Invoke: `/agent-architect`
   - Wait for completion
   - Save results to: `.gsd/phases/phase-N/ARCHITECTURE.md`
```

## ✅ Benefits

### Why This Integration Works

1. **No Duplication**: Each skill does what it's best at
   - agent-architect = AI architecture design
   - GSD = systematic implementation

2. **Context Preservation**: Architecture flows naturally
   - ARCHITECTURE.md → planning → implementation
   - Fresh context per task prevents degradation

3. **Flexibility**: Works for pure AI or mixed projects
   - Pure AI: Multiple phases with agent-architect
   - Mixed: Some phases AI, some standard

4. **User Control**: Semi-automatic
   - GSD detects and suggests
   - User approves invocation
   - User approves architecture
   - User approves plans

5. **Maintainability**: Update one skill, benefits propagate
   - Fix agent-architect interview → all GSD projects benefit
   - Improve GSD workflow → all integrations benefit

---

## 🚫 When NOT to Use Integration

Skip agent-architect invocation when:

1. **Simple automation** - basic scripts, not true agents
2. **Single LLM call** - just need Claude API, not agents
3. **No architectural complexity** - straightforward implementation
4. **Time constraints** - agent-architect adds 20-30 min

For these cases, use standard GSD discuss/plan.

## 🎓 Learning Path

### First Time Using Integration

1. Start with **pure AI project** (easier to understand)
2. Let GSD detect the AI phase
3. Approve agent-architect invocation
4. **Read ARCHITECTURE.md carefully** - this guides everything
5. Follow the plans GSD creates
6. Observe how fresh context per task works

### Advanced Usage

1. **Mixed projects** - AI components within larger systems
2. **Manual triggering** - invoke agent-architect when you realize you need it
3. **Architecture iteration** - re-run agent-architect if design changes
4. **Skill packaging** - use agent-architect Phase 6 to save the system as a skill
